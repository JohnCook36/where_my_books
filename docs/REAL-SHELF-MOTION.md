# Real Shelf и motion — этап D, 2026-10-17

Shelf остаётся шкафом, ShelfSection — секцией; StorageRoom и ShelfRow добавляют комнату и физическую полку. Ничего из прежней модели/истории миграций не удаляется. BookCopy имеет одно физическое размещение либо находится вне полок.

Раскладка PostgreSQL — источник истины. Все изменения получают requestId/baseRevision, сериализуются по владельцу, сохраняют receipt для повтора запроса. Другой payload того же requestId и stale revision отклоняются409. Undo move/sort требует актуальной ревизии последней операции; не затирает изменения с другого устройства. Удаление занятого контейнера требует явного назначения другой полки либо явного снятия книг с полок; copies сохраняются. Ограничение вместимости — количество экземпляров, не обещание расчёта реальных миллиметров.

Motion: короткая отдача при нажатии, мягкий lift при выборе/long press, прямое следование пальцу, сдвиг соседей к месту вставки, пружина при отпускании, спокойное появление на целевой полке и плавная полупрозрачная заливка прогресса. Общие tokens; без experimental shared-element переходов и тяжёлой3D. Reduce Motion отключает декоративное движение и layout transitions; прямое управление drag сохраняется. UI-thread worklets не вызывают React setState на каждом кадре. Статус сохранения зависит от API, а не окончания анимации.

В первом срезе D: DnD внутри выбранной полки, доступный перенос через модальный выбор места между комнатами/шкафами/секциями/полками, Undo, поиск физического пути и подсветка. Межстрочный drag/edge auto-scroll, размеры в миллиметрах/fit, полный дизайн всех режимов и последующая native-приёмка остаются дальнейшей частью D. Не считать код или JS bundle доказательством плавности на телефоне. По решению владельца Android manual проверяется после сборки функциональности.

## Реализованный контракт

`GET /api/shelves/layout` возвращает согласованный repeatable-read snapshot комнаты/шкафы/секции/полки/placements и revision. `POST /api/shelves/layout` принимает requestId UUID, baseRevision и строго валидированный action: create_room/create_shelf/create_section/create_row/rename/delete/move/sort/undo. Шкаф создаёт заданные1–8секций и1–12полок на секцию; полка имеет1–200мест. Move принимает1–50своих copyIds и rowId либо явный null; beforeCopyId выбирает точную позицию вставки, иначе добавление в конец.

Composite owner FKs в PostgreSQL связывают room→shelf→section→row и placement→copy/row; одна copy уникальна, (rowId,position) уникальна. Транзакция переписывает только затронутые полки в плотный порядок0…N−1, по возможности сохраняя placement IDs. Никакие books/work/edition не удаляются вместе со шкафом. Удаление самой книги берёт тот же layout lock, уплотняет полку и меняет revision, блокируя устаревший Undo.

Receipts сохраняют request hash/result revision и приватный snapshot порядка для Undo move/sort. Replay проверяется до baseRevision: потерянный ответ можно повторить после других изменений без нового move. Stale/conflicting request409 не применяется. Receipt retention до production требует отдельной политики; сейчас история не очищается автоматически.

Мобильный экран содержит настоящие create/rename/delete, три темы шкафа, выбор и сортировку полки, виртуализованный поиск/выбор книг, перенос группы до50 и Undo. Book API возвращает location/path, карточка и библиотека показывают физический путь. Из результатов подтверждения scan batch можно разместить сохранённые copies на общей полке; ошибка размещения не отменяет уже сохранённые книги. %/страницы загружаются из глобальных settings на главной/в библиотеке/details/RealShelf.

Отрисовывается одна активная физическая полка, не вся коллекция в несколько тысяч copies. Она ограничена200корешками; search/book picker использует FlatList. Drag ведётся на UI thread, preview обновляет React только на отпускании. При неоднозначной сетевой ошибке блокируются новые мутации и предлагается повторить тот же requestId; подтверждение показывается только после ответа API и свежей загрузки. Нет независимой офлайн-библиотеки. Анимация не является подтверждением сохранения.

Общее reduce-motion состояние подписывается на OS один раз, live updates передаются через context; декоративные lift/scale/entry/layout отключаются, прямое следование пальцу допустимо. Окна используют один native Modal host, чтобы переход к вложенному выбору не создавал competing iOS presentations. Все новые motion/геометрия/палитры — в ui tokens. Перемещение доступно и без жеста.

## Проверки и открытые части D

Shared tests: строгие action bounds, UUID normalization, явное снятие с полки, stable insertion и worklet geometry для разных ширин/краёв/соседних gap. PostgreSQL HTTP suite: account isolation и реальное отклонение foreign composite FK, create/replay/CAS/capacity, dense positions, reorder/sort/Undo/restart, deletion revision, безопасное удаление с переносом/снятием copies и группа50 с replay/Undo. Успех фиксируется только после CI текущего SHA.

Native плавность/gesture arbitration/ReduceMotion/TalkBack/VoiceOver, большие шрифты и FPS/память на среднем устройстве не проверены. Межстрочный drag и edge autoscroll, реальная вместимость по миллиметрам, полный grid/list/spines режимов, настройка размеров/цветов копий, дополнительные свойства шкафов и sync/offline остаются дальнейшей работой. Текущий BookCopy не имеет полного бумага/ebook/audio lifecycle; ввод такой модели должен запретить физическое размещение неподходящего формата. D целиком не закрывается, stage I release не выполнен.
