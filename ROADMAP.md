# Roadmap — BookNook / WhereMyBooks

Этот файл является рабочим планом разработки. Мы идём по нему последовательно и не начинаем следующий этап, пока не закрыты критерии завершения текущего.

## Правила работы

1. Разрабатываем сначала мобильное приложение.
2. Баги можно исправлять вне очереди, если они мешают текущему этапу или уже реализованному функционалу.
3. Новая фича, не относящаяся к текущему этапу, не реализуется сразу. Сначала отмечаем, к какому этапу она относится.
4. Если предлагаемая задача уводит нас в сторону, это явно обозначается сообщением: `⚠️ Это отход от roadmap` с указанием правильного этапа.
5. Переиспользуемые UI-компоненты и design/motion tokens выносим в `ui`.
6. Чистые типы, доменную логику, контракты и утилиты выносим в `shared`.
7. `client`, `server`, `mobile`, `ui`, `shared` остаются соседними top-level workspace.
8. Каждая крупная функциональность должна проходить как минимум `typecheck` и `lint` перед завершением этапа.
9. Не используем `npm audit fix --force` без отдельного анализа влияния на Expo и native-зависимости.
10. Плавность, микровзаимодействия и тактильность интерфейса считаются частью функциональности, а не финальным косметическим этапом.

# Этап 6. Каталог книг, обложки и ISBN

Цель: убрать большую часть ручного ввода.

Сначала поднимаем минимально необходимую серверную интеграцию, не превращая этап в полный backend rewrite.

- [ ] единый provider interface для книжных источников;
- [ ] Google Books как основной metadata provider;
- [ ] Open Library как fallback;
- [ ] поиск по названию;
- [ ] поиск по автору;
- [ ] поиск по ISBN;
- [ ] выбор конкретного издания;
- [ ] загрузка обложек;
- [ ] ручная коррекция полученных метаданных;
- [ ] barcode scanner на мобильном;
- [ ] добавление книги после сканирования ISBN;
- [ ] кеширование результатов, чтобы не зависеть от внешнего API при каждом открытии.

**Критерий завершения:** большинство физических книг можно добавить за несколько секунд через поиск или штрихкод.
